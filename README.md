# WordPress-плагіни для економії місця на сервері

Автор: **Zaichenko Andrey** — [websites-service.com](https://websites-service.com/)

У репозиторії два незалежні плагіни. Їх можна ставити разом або окремо.

| Плагін | Що робить |
|---|---|
| [WS Image Optimizer](ws-image-optimizer/) | Стискає зображення, за потреби конвертує JPEG/PNG у WebP і видаляє оригінали |
| [WS Video Optimizer](ws-video-optimizer/) | Стискає відео у MP4 (H.264) через FFmpeg без видимої втрати якості й видаляє оригінал |

## Встановлення

1. Завантажте архів потрібного плагіна з папки [`dist/`](dist/):
   - [`ws-image-optimizer.zip`](dist/ws-image-optimizer.zip)
   - [`ws-video-optimizer.zip`](dist/ws-video-optimizer.zip)
2. У WordPress: **Плагіни → Додати новий → Завантажити плагін**, оберіть архів і активуйте його.
3. Налаштування з'являться в меню **Медіафайли → Оптимізація зображень** / **Оптимізація відео**.

Або через WP-CLI на сервері:

```bash
wp plugin install https://github.com/prorabra/wp/raw/main/dist/ws-image-optimizer.zip --activate
wp plugin install https://github.com/prorabra/wp/raw/main/dist/ws-video-optimizer.zip --activate
```

> Для приватного репозиторію пряме посилання не спрацює: скачайте zip на GitHub, увійшовши в акаунт.

## WS Image Optimizer

**Що робить**

- Під час завантаження в медіатеку стискає зображення (якість за замовчуванням 82, різниці на око не видно).
- Конвертує JPEG і PNG у **WebP** (якщо сервер це підтримує). Прозорість PNG зберігається.
- Зменшує надто великі фото до заданої найбільшої сторони (за замовчуванням 2560 px, як у самому WordPress). 0 — не змінювати розмір.
- **Видаляє оригінал**, тому на сервері лишається тільки оптимізований файл і його мініатюри. WordPress більше не зберігає повнорозмірну копію поруч із «-scaled».
- Якщо після стиснення файл не став меншим, залишає оригінал без змін.
- **Пакетна обробка** вже завантажених JPEG/PNG однією кнопкою, з оновленням посилань у записах, сторінках і даних конструкторів (наприклад Elementor).
- GIF (анімація) та SVG не чіпає.

**Вимоги:** WordPress 6.0+, PHP 8.0+, Imagick або GD з підтримкою WebP.

**WP-CLI:** `wp ws-image bulk` обробляє всю медіатеку без обмежень браузера.

## WS Video Optimizer

**Що робить**

- Після завантаження відео ставить його в чергу й у фоні стискає через **FFmpeg** у MP4: відео H.264, звук AAC.
- Якість задається CRF: **23** за замовчуванням, різниці з оригіналом на екрані не видно, а файл зазвичай у 2–10 разів менший. 18–20 дає майже повну відсутність втрат.
- Відео 4K за замовчуванням зменшується до 1080p. Менші відео ніколи не збільшуються, а 0 зберігає роздільність оригіналу.
- Додає `faststart`: відео починає грати ще до повного завантаження.
- **Видаляє оригінал** після успішного стиснення. Якщо файл був `.mp4`, ім'я лишається тим самим, тому посилання не змінюються. Для `.mov`, `.avi` тощо посилання в записах оновлюються.
- Якщо стиснений файл виходить більшим за оригінал, оригінал залишається.
- Відео обробляються по одному з найнижчим пріоритетом процесора (`nice`), щоб сайт не гальмував.
- Сторінка зі статусом кожного відео та скільки місця зекономлено. Вже завантажені відео можна поставити в чергу однією кнопкою.

**Вимоги:** WordPress 6.0+, PHP 8.0+, **FFmpeg на сервері** і дозволена PHP-функція `exec()`. На сторінці плагіна є перевірка сервера. Якщо FFmpeg лежить не в стандартному місці, шлях вказують у `wp-config.php`:

```php
define( 'WSVO_FFMPEG', '/home/user/bin/ffmpeg' );
```

Шлях навмисно не можна змінити з адмінки, щоб через форму не можна було запустити сторонню програму.

**Великі відео.** Звичайний WP-Cron запускається з відвідуваннями сайту, і хостинг може обірвати довгий процес. Для великих файлів налаштуйте системний cron або запускайте через WP-CLI:

```bash
wp ws-video queue-all   # поставити всі необроблені відео в чергу
wp ws-video run         # обробити чергу зараз
```

## Важливо

- **Зробіть резервну копію** файлів і бази даних перед пакетною обробкою. Оригінали видаляються без можливості відновлення.
- Видалення оригіналу можна вимкнути в налаштуваннях кожного плагіна.
- Чесно про «без втрати якості»: стиснення, яке реально зменшує файл, завжди відкидає частину даних. Налаштування за замовчуванням підібрані так, щоб різниці не було видно на сайті. Для максимальної якості ставте CRF 18–20 для відео і якість 90 для зображень.

## Безпека

- Усі дії в адмінці доступні лише адміністраторам (`manage_options`) і захищені nonce.
- Видаляються тільки файли всередині папки `uploads`, з перевіркою реального шляху.
- Усі аргументи команди FFmpeg екрановані, налаштування перевіряються за білим списком.
- Увесь вивід в адмінці екранується, а прямий доступ до PHP-файлів заблоковано.
